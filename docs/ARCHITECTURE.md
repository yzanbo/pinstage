# コードの構成

画面と文書の言葉と、コードの中の名前は、次のように対応する（コードの名前は、画面に出ないので変えていない）。

| 画面・文書の言葉 | コードの名前 |
|---|---|
| ウインドウバー（画面の端の、ウインドウとグループの一覧） | Strip（StripController・StripSettings など）。URL も pinstage://strip/… のまま |
| ステージ（ウインドウを前に出して並べる場所。画面からメニューバー・Dock・ウインドウバーを除いた残り） | 場所は stageArea・StripGeometry.stageFrame |
| ステージに出ているウインドウ（前に出して並べている組み合わせ。名詞は作らない） | Stage（StageBoard.Stage・StageSelection など） |

## 決まりごと

- **決められることは PinstageCore で決める**：AppKit を使わずに決められること（並べ方から枠を出す・グループと型の書き換え・デスクトップの判定）は PinstageCore に置いて、テストを付ける。アプリ側は、読んだ値を渡して、決まったことを行うだけにする
- **グループと型の書き換えは 1 つの入口から**：書き換えは StageLibrary の関数で行い、StageController の `editLibrary` で包む（変わったときだけ保存して、「ショートカット」アプリに知らせる）。
  グループの中身は、ステージから作っても、見えている画面を記録して作っても、同じ形（StageGroup.Content）にしてから入れる

- **見た目は「形式」で決める**：形式は、アイコンの並び・一覧・サムネイルの 3 つ。行の描き方は、形式と大きさ（小・中・大。どの形式にもかかる）から StripRowKind で決める（ビューは StripRowKind だけを見る。一覧の行の高さ・アイコン・文字、サムネイルの高さの下限、アイコンの並びのアイコンは、StripIconSize が持つ）。「小」は、一覧・サムネイルのいままでの大きさ。
  「たたむ」という状態は持たない。細い帯にしたいときは、アイコンの並びの幅を 1 列まで狭める（アイコンの並びの幅 gridWidth は、一覧・サムネイルの幅 stripWidth とは別に覚えるので、形式を切り替えるだけで行き来できる）。
  幅がふつうの下限（160pt）より狭いときは、上の帯・グループを、アイコンだけにして縦に並べる（StripGeometry.usesCompactChrome。幅を変えるドラッグの途中も、その幅で決める）
- **位置は「辺」と「厚み」で決める**：ウインドウバーは画面の上下左右のどの辺にも置ける（StripSettings.edge）。位置の計算（StripGeometry）・ウインドウをよける判定（StripAvoidance）は、辺と厚み（左右なら幅、上下なら高さ）を受け取り、辺ごとの分かれ目はそこに閉じ込める。
  左右は縦長の帯で、幅をドラッグで変えられる。上下は横長の帯で、高さは行の描き方（StripRowSizing.barThickness）で決まる。ビューは `strip.isHorizontal` で、縦に並べるか横に並べるかを分ける（行そのものは同じ）
- **並べ替えの行の枠は、ずらしの外側で測る**：SwiftUI では、offset の内側で測った枠には、ずらした量が入る。内側で測ると、ドラッグしている行（と、一緒に動く行）の枠がポインタについて動き、
  落とす位置の判定が自分の行に引っかかって、線が出ない・ちらつく（行の上半分をつかむと起きる）。枠は、ReorderDrag のいちばん最後（ずらしの外側）で測る。
  同じ理由で、動いている行を手前に描く zIndex は、行のいちばん外側に付ける（あとにほかの修飾が続くと効かない。ReorderState.isMoving）
- **ウインドウの開け閉めは、すぐ一覧に映す**：1.5 秒ごとの読み直しのほかに、ウインドウの知らせ（StripAvoider の AXObserver）と、画面に出ているウインドウの一覧（0.3 秒ごとに番号だけを比べる。軽い）が変わったときに読み直す。
  × で閉じてもウインドウを捨てずに隠すだけのアプリ（LINE など）は、閉じた知らせを出さず、macOS も元のデスクトップにあるものとして扱い続けるので、「いま見ているデスクトップにあるのに画面に出ていない（最小化・アプリを隠したものは除く）」ことで隠されたと見分け、ウインドウバーに並べない（PinstageCore の HiddenWindows。並び順の記録には残す）。デスクトップを切り替えた直後の 1 秒は見分けない
- **並べたあとに確かめ直す**：枠を変えたあと、0.3 秒待って実際の枠を読み直し、ずれていたら合わせ直す（しまってあったウインドウ・大きさを遅れて当てるアプリのため。StageController.checkPlacements）。それでもずれたもの（アプリがそれより小さくできないなど）は、記録（desktops.log の「並べたときのずれ」）に残す
- **Dock・メニューバーとの重なり**：ウインドウバーは、ディスプレイの使える範囲（visibleFrame）の中に置く。常に表示している Dock・メニューバーはこの範囲から除かれているので、同じ辺に置いても内側に並ぶ。
  「自動で隠す」のときに出すきっかけは、画面そのものの端（Dock の外側）なので、ウインドウバーと画面の端との間にポインタがある間は「離れた」とみなさない（StripGeometry.shouldHide）。
  自動で隠れる Dock・メニューバーは使える範囲から除かれず、出てきたときにウインドウバーの上に重なる（どちらもウインドウバーより手前）。これは防げないので、macOS の設定を読んで（SystemBars）、設定の「位置」に案内を出す。
  Dock の設定を変えると使える範囲が変わるが、画面の構成が変わった知らせが来るとは限らないので、読み直すたびに使える範囲を比べ、変わっていたらウインドウバーを置き直してステージのウインドウを並べ直す（StripManager.followUsableAreaChanges）
- **ウインドウバーの高さ**：ふつうのウインドウより上、「最前面に出す」ウインドウ（.floating）より 1 つ下（floating − 1）。pinshot のピンなど、利用者が最前面に置いたものをウインドウバーより上に出すため（同じ高さだと、出した順で上下が入れ替わる）
- **ウインドウバーはデスクトップごと**：すべてのデスクトップに付いて回ると、切り替えの途中に前のデスクトップの一覧が見えるので、デスクトップごとに置く（isOnActiveSpace で、いまのデスクトップのものを見分ける）。ウインドウは .stationary にしない（付けると切り替えのスライドの間も画面に留まり、行き先のデスクトップの上に前の一覧が残る）。ふつうのウインドウ（managed）にして、置いたデスクトップと一緒にスライドさせる。隠すときは画面から外さず（外すと置いたデスクトップを忘れるため）、透明にして画面の外へ置き、クリックを素通りさせる
- **デスクトップは非公開の API で直接見分ける**：デスクトップを扱う公開の API はないので、非公開の関数（SkyLight）を使う。
  起動したとき、すべてのディスプレイのすべてのデスクトップ（フルスクリーンのものは除く）に、前もってウインドウバーを置く（自分のウインドウを、見ていないデスクトップへ移せる）。
  デスクトップを足した・消したら、読み直しのたび（1.5 秒ごと）と切り替えたときに合わせる。各ウインドウバーは、自分のデスクトップにあるウインドウだけを並べる。
  ウインドウは macOS のウインドウの番号で見分ける（画面に出ているか・重なりの順番・サムネイルの照合）。
  すべてのデスクトップに割り当てたウインドウは、そのディスプレイのすべてのデスクトップに属する（ウインドウのあるデスクトップが 2 つ以上返る）ので、どのウインドウバーにも並べ、行に「すべて」の印を付ける（ほかのデスクトップの番号の印は付けない。PinstageCore の WindowSpaces）。
  ほかのデスクトップのウインドウは、アクセシビリティの API の一覧に出てこないアプリが多いので、RemoteWindows で見つけて一覧に足す（起動直後から、すべてのデスクトップのウインドウが分かる）。
  見つからなかったものは 30 秒たつまで探し直さない。ほかのデスクトップのウインドウを押したら、そのデスクトップへ移って前に出す（SkyLight.focus）。
  グループは、保存したデスクトップのウインドウバーにだけ並べる。デスクトップは、番号（ManagedSpaceID。再起動で変わることがある）ではなく、
  macOS が設定ファイル（com.apple.spaces）に保存している UUID で覚える（StageGroup.desktopID。nil ならすべてのデスクトップ。前の版のグループも nil）。
  覚えた UUID のデスクトップがもうなければ、どこにでも並べる（呼び出せなくならないように）。
  関数が見つからないとき（macOS が変わったときなど）は、下の推測の仕組みに自動で戻る
- **一覧はウインドウバーが持つ**（非公開の API が使えないときの推測の仕組み）：ウインドウバーは、自分のデスクトップのウインドウの一覧を持ったままにする（ほかのデスクトップを見ている間も変えない）。切り替えの動きの途中から、行き先の一覧が出ているようにするため。
  「画面に出ているウインドウの一覧」（CGWindowList）を読んだとき、同じ一覧に出ているウインドウバーが、そのデスクトップのウインドウバー（操作スペースの公開の API がないので、ウインドウバーのウインドウを目印にする）。
  切り替えの途中は両方のデスクトップのウインドウとウインドウバーが画面に出ているので、そのときの一覧は覚えさせない（覚えさせると、行き先のウインドウバーに前のデスクトップのウインドウが混ざる）。
  切り替えの知らせ（activeSpaceDidChange）は動きが終わる前に来ることがあるので、知らせのあと、落ち着くまで少しずつ読み直す。
  最小化したウインドウ・隠したアプリのウインドウは、覚えた一覧とは別に、どのウインドウバーにも並べる。フルスクリーンのウインドウは、デスクトップの一覧に入れない

- **ステージはウインドウを抱え込まない**：ステージに出すのは「最前面に出すウインドウの組み合わせ」。出したり外したりしても、保存したグループは変わらない
- **ディスプレイごとのステージ**：ウインドウバーを押したディスプレイのステージを変える。1 つのウインドウは 1 つのステージにだけ入る（別のディスプレイのステージに入れたら、前のステージから外れる）。`StageBoard.update` が外れたディスプレイを返し、`StageController.updateStage` がその残りを詰めて並べ直す（前には出さない）
- **ウインドウを別のディスプレイへドラッグ**：バー内の並べ替えの行はスクロール欄で切り取られるため、外では `StripWindowDragFeedback` がマウスを受け取らない別パネルで見本を出し、行き先のバーの枠を光らせる。行き先のバーの `windowReorder` に落とす位置を入れて、同じバーの中と同じ線を出す。離したら `StageController.move` で、そのディスプレイのステージをそのウインドウだけにし、線の位置に並べる。並べ替えのはみ出しは同じディスプレイの中だけで許す（`StripDragGeometry`）
- **デスクトップ別の切り替え一覧**：分類時に読んだデスクトップとウインドウの所属を使い、`DesktopWindowList` で所属ごとに分ける。ショートカットからも、ウインドウバーのボタンからも、同じ切り替え画面（全体）を、前面アプリを変えない `KeyboardPanel` で、そのディスプレイの真ん中に出す。ボタンから開いたときは、押したデスクトップの最初のウインドウを選んでおく（`DesktopPickerModel(focusing:)`）。確定時だけ、ほかのデスクトップにも対応した既存のフォーカス処理で前に出し、ステージへの配置処理は呼ばない。デスクトップの所属と順番は `StageController.desktopListGroups` で一度決める。スイッチャーの「デスクトップ別」ではグループを名前付きの枠で表示し、開いたディスプレイの枠とその現在のデスクトップを先頭にする。メインのバーに複数ディスプレイの個別ボタンを出すときも同じグループ情報を使い、個別ボタンの領域は `StripDesktopButtonLayout` で計算する。所属不明のウインドウはディスプレイの枠の外に並べる
- **切り替え画面の操作**：初期設定ではショートカットに登録された修飾キーを覚え、`KeyboardPanel` に届くキーの変化を `WindowSwitcherRelease` で受け、すべて離したときに一度だけ確定する。表示までに離していたら、表示直後の確認で確定する。確定方法を「Enter」にした場合と、ウインドウバーのボタンから開いた場合は、自動確定を待たない。ショートカットで開いている間、同じショートカットを押すと確定方法にかかわらず次へ進む。文字は絞り込み（`WindowSwitcherFilter`。検索と同じ `SearchMatcher`）、スペースは並べる候補（いまのデスクトップのウインドウだけ。↩ で `StageController.present`）
- **アプリのバッジ**：`DockBadges` は標準の `AXStatusLabel` を読み、`PublishedAppBadges` は置き場（`Application Support/Pinstage/BadgeSources`）にある `<バンドル ID>.json` を、相手のアプリを名指しせずに全部読む（形式は [BADGES.md](BADGES.md)。Kickoff もその 1 つ）。有効な連携データ（空配列も含む）を優先し、なければ標準に戻す。起動中のアプリとファイルを照合し、2 秒に 1 回まで。バッジのデータは `AppIconBadge`、アイコンとバッジの描画は `WindowAppIcon` を両方の画面で共有する。アイコンの右下は「すべてのデスクトップ」の印に使う
- **ショートカットの切り替え画面の設定**：`WindowSwitcherSettings` のグループ分け・見た目・大きさは独立し、ウインドウバーのボタンから開いたときにも同じ表示を使う（初期設定はデスクトップ別・アイコンだけ）。画面の高さと列数は中身に合わせる（`WindowSwitcherLayout`。ビューも同じ寸法で描く）。サムネイルを選ぶときは設定画面とスイッチャーで保存・許可確認の処理を共有する。切り替え画面の中でも変えられ（右上の切り替え・⌘G・⌘1〜3）、変えた値はそのまま設定に残す。表示を変えたら、パネルを中身に合う大きさにし、列の数を合わせ、選んでいるウインドウを探し直して保つ（`DesktopPickerModel.setGrouping`・`setAppearance`）。まとめて表示するときは `WindowFocusHistory`（起動中に観測したフォーカス）で順番を決め、同じウインドウは一度だけ出す。サムネイルは既存の画像を再利用し、足りないものは画面内のカードから非同期で撮影する。閉じたら撮影の処理をキャンセルする
- **外で前に出したウインドウに選択を合わせる**：`StripAvoider` の受け取り口で、前面アプリの切り替え（NSWorkspace）とアプリ内のフォーカスの変更（AXObserver）を拾う。デスクトップの切り替えや定期的な読み直しでも確かめる。前面アプリのフォーカスが、画面に出ているウインドウバーの対象に変わったら、`StageBoard.followFocus` で選択だけを更新する。組み合わせ内ならそのまま。組み合わせ外ならそのウインドウだけを選び、位置・大きさ・並べ方は変えない。Pinstage が並べて前に出す間は、途中のフォーカス変更で選択を崩さない
- **型とグループを分ける**：型は並べ方の形だけ（どのアプリかは覚えない）。グループは「どのウインドウを、どの型で、どのディスプレイに」並べるか
- **座標**：ウインドウを動かす計算は、アクセシビリティの API と同じ「左上が原点」でする。ウインドウバーの位置は AppKit の「左下が原点」でする。変換は `ScreenCoordinates` だけで行う
- **1 枚だけ出すとき**：用意した型では、設定の大きさ（そのまま・縦いっぱい・ステージいっぱい）で前に出す
- **サムネイル**：ウインドウバーに並べているウインドウだけを、3 秒ごとに撮り直す（ウインドウバーを隠している間・大きさが「小」のときは撮らない）。撮った画像は保存も送信もしない
- **App Sandbox は使わない**：ほかのアプリのウインドウを動かすため（アクセシビリティの API はサンドボックスの中では使えない）

## 割り切っていること

- 別の操作スペースのウインドウは、多くのアプリでウインドウの一覧に出てこない。前に見えていたウインドウは、閉じるまで一覧とステージに残す（まだ見ていないスペースのウインドウは出ない）。ウインドウバーには、いまのスペースのウインドウだけを並べる（CurrentSpace。公開の API だけで、アプリ・位置・名前で見分ける。画面収録の許可がないと名前が分からず、同じ位置・大きさのウインドウを取り違えることがある）
- ウインドウの読み直しは、画面の処理と同じ流れで行う（変わったときだけ描き直す）。応答しないアプリがあると、一瞬止まることがある

- 登録した型の前後の順番は、前に出した順番で覚える（いまの並びから型を作るとき、実際の重なりの順番は読まない）
- 見えている画面の記録では、重なりの順番を画面に出ているウインドウの一覧（CGWindowList。前から後ろの順）から読む。ウインドウとは、アプリ・名前・枠で照らし合わせる（CurrentSpace.frontToBack）。照らし合わせられなかったウインドウは記録に入らない。記録した枠はステージに対する割合で覚えるので、ステージの外（ウインドウバーの後ろなど）にはみ出したところは切れる
- 記録したグループを呼び出したとき、見つからなかったメンバーの枠は抜いて当てはめる（ほかのウインドウの枠がずれないように）
- （非公開の API が使えないときだけ）初めて訪れたデスクトップには、着いてからウインドウバーを作る（まだ見ていないデスクトップにウインドウを置く公開の API がない）。そこへの切り替えの途中に、前のデスクトップのウインドウバーへ紛れ込んだウインドウは、着いたあとで外す（入ってから 5 秒までのもの）
- ほかのデスクトップのウインドウバーの一覧は、最後にそのデスクトップを見たときのもの。見ていない間にそのデスクトップで開いた・移したウインドウは、着いてから一覧に入る
- 自分のウインドウを出した・動かした結果は、次の描画まで「画面に出ているウインドウの一覧」に出てこない。作ったばかりのウインドウバーは、1 秒までは一覧になくても、いまのデスクトップにあるものとして扱う
- サムネイルのウインドウは、アプリ・名前・枠で照らし合わせる（非公開の API でウインドウの番号を読むことはしない）
